# Storage, jobs and real-time delivery

## Objects

| Purpose | Input | Limit | Access and retention |
| --- | --- | --- | --- |
| Brand/static references | Approved repository asset | Versioned | Public |
| Team/community/tournament image | JPEG/PNG/WebP | 10 MiB, max 8192 pixels per side | Public only when owning record permits |
| Scoreboard evidence | JPEG/PNG/WebP | 10 MiB (10,485,760 bytes), max 16,777,216 decoded pixels and 8192 pixels per side; decode/orientation normalization within 5 seconds | Participants/reviewers; retained with match audit |
| External achievement evidence | Image or HTTPS reference | Same image bounds | Profile owner; public only by explicit visibility |
| Biometric crop | JPEG/PNG/WebP emitted after the frontend `@vladmandic/human` pipeline accepts exactly one face, completes the configured blink/liveness/anti-spoof capture gate and produces the aligned crop; maximum 4,194,304 decoded pixels | 2 MiB (2,097,152 bytes) | Dedicated biometric request path only; bounded in-memory stream/decode, never an asset/object, temp file, log, backup or provider payload; discard on every outcome |

General asset API receives multipart file, validates media signature and dimensions, computes SHA-256, writes an unpredictable object key, then records asset metadata. Biometric input does not take this asset path: it is byte-capped before read, decoded with a pixel ceiling, rejects unsupported/animated input, strips metadata in memory, and must not use framework upload spooling that persists raw bytes. Frontend `@vladmandic/human` handles face-count validation, alignment and the browser blink/liveness/anti-spoof gate; the backend does not repeat detection. Reject SVG uploads; transferred passive brand SVG is trusted reference content only. Failed database commit leaves a cleanup candidate, never a visible orphan. Store object keys rather than expiring URLs or data URLs. API serves authorized object bytes at /api/v1/assets/{id}/content; cache only approved public assets. Bucket bootstrap is an onsite operator task.

Scoreboard evidence remains a private asset. Before it is persisted or queued, intake verifies media type, byte/pixel/side limits, decodes within five seconds, applies EXIF orientation in memory and strips metadata from the processing image. Its worker receives the private asset reference plus frozen lineup snapshot, not an externally addressable URL. RF-DETR detection boxes, detector-crop PaddleOCR diagnostics, local template candidates and reviewer corrections are audit/draft data; the source screenshot is never included in logs, provider prompts or public projections. A decoded valid image whose geometry cannot attest `mlbb_post_match_v1` is `NEEDS_REVIEW` with `UNSUPPORTED_LAYOUT`; it does not go through another parser. No OCR-provider fallback exists. See [MLBB extraction](MLBB_SCOREBOARD_EXTRACTION.md).

## Durable jobs

Persist job kind, aggregate ID, payload reference, idempotency key, status, attempts, available_at, lease expiry and last error. States: PENDING, RUNNING, SUCCEEDED, FAILED. Worker lease is 120 seconds with heartbeat for long OCR; expired lease returns to pending. Retry transient local infrastructure failures after 5, 30 and 120 seconds; permanent evidence/artifact/catalog validation failures stop. A run timeout, missing local artifact or parse failure never fabricates a result or invokes another provider. Initial OCR concurrency is one; separate resource budget from API.

Kinds: OCR extraction, bracket synchronization, notification delivery, provider reconciliation, certificate submission/reconciliation, and operator-requested Solana escrow release/reconciliation. PayMongo reconciliation is test-mode entry checkout only: it receives a signature-verified receipt, reconciles the expected Checkout Session/payment and exact PHP-centavo snapshot, and can never create Wallet, recipient, transfer, payout, refund or live-mode work. Solana jobs only read the configured Devnet/genesis at finalized commitment, reconcile the original signature/PDA/Core asset, and sign no replacement transaction after a timeout. Certificate submission stores the server-derived metadata/image URI/SHA-256 and public-read evidence, persists its candidate Core address before broadcast, and verifies a Core NFT with `PermanentFreezeDelegate(frozen: true, authority: None)`, no collection and no update authority before issue. An ambiguous send moves only that record to `PENDING_RECONCILIATION`; no worker retry signs a different asset. Escrow release can run only from PCC's immutable two-recipient allocation. There is no timed scrimmage finalizer. Never let a periodic job change a submitted scrimmage winner.

## WebSocket contract

Endpoint /ws/events; same-origin session authentication. Server derives permitted user/team/community/tournament channels. Client may request entity subscriptions but cannot self-authorize them. Event envelope fields: event_id, type, aggregate_id, version, occurred_at and minimal payload. Event types: match.recorded, bracket.updated, scrimmage.matched, scrimmage.finalized, comment.created, notification.created, reward.updated, certificate.updated.

Emit only after commit. Client de-duplicates event_id and refetches when version skips or after reconnect. Reconnect delays 1, 2, 5, then 15 seconds capped. Persist comments and notifications before delivery. Redis outage delays live updates without losing committed data; UI allows refresh and shows reconnecting state.
