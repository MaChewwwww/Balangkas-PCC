# Application configuration contract

**Status: preparation contract only.** Secret values are never committed. After onsite activation, the application reads an ignored application environment file on the VPS; Compose receives only the variables needed to launch services. Validate the configuration before a rollout and fail closed when a required value is missing or malformed.

## Runtime configuration

| Variable | Required where | Purpose and safe behavior |
| --- | --- | --- |
| `PCC_ENVIRONMENT` | all application processes | Exact deployment mode. Allowed values are `development`, `staging` and `production`; any other value stops startup. The hackathon VPS uses `staging`. |
| `PCC_PUBLIC_ORIGIN` | API and frontend | Exact HTTPS public origin used for Origin checks, links and cookie policy. It must not contain a path or wildcard. |
| `PCC_SESSION_SIGNING_KEY` | API | High-entropy session-signing secret. Missing/weak values stop startup; it is never logged. The tracked example intentionally contains an obvious replacement placeholder only. |
| `PCC_SESSION_TTL_SECONDS` | API | Explicit session lifetime; the preparation template selects `86400` seconds (24 hours). A runtime default is prohibited so an accidental long-lived session cannot be created. |
| `PCC_CSRF_TOKEN_TTL_SECONDS` | API | Explicit lifetime/rotation policy for session-bound CSRF tokens; the preparation template selects `86400` seconds and it must not exceed the session lifetime. |
| `PCC_CORS_ORIGINS` | API | Optional, exact allow-list for a separately approved first-party origin. It is unset for the same-origin hackathon deployment; `*` and credentialed wildcard CORS are invalid. |
| `PCC_OPENAPI_EXPOSED` | API/proxy | Public API documentation switch. The staging template preselects it `true` at the user's direction so the hackathon contract is available by default. It must be an exact boolean; malformed values stop startup. Published documentation must never serialize secrets, private examples, internal host paths or provider diagnostics. |
| `PCC_HACKATHON_DEMO_OTP_ENABLED` | API | Explicit boolean allowing the configured demo OTP only when `PCC_ENVIRONMENT=staging`. The preparation template preselects it `true` at the user's direction; true in any other environment stops startup. See [API integration](API_INTEGRATION.md#hackathon-demo-otp-exception). |
| `PCC_HACKATHON_DEMO_OTP_CODE` | API | Committed non-secret hackathon cheat code, fixed to `123456`. It is read only when the demo flag is enabled in exact staging; it must not be exposed through browser configuration or treated as provider, biometric, wallet, payment, or settlement evidence. Missing or altered values leave the bypass unavailable. |
| `PCC_MAINTENANCE_ENABLED` | API | Explicit operator-controlled maintenance mode. When true, mutations return the documented maintenance response while authorized reads remain available unless a separate approved quiesce is active. |
| `PCC_FACE_MODEL_PATH` | biometric API adapter | Absolute in-container path for the manually provisioned, read-only W600K-R50 artifact. The ignored `.env.application` is populated from `.env.application.example` with `/models/face-recognition/w600k_r50.onnx` for the standard Compose mount. It must resolve to the exact file and SHA-256 in [the face-model record](FACE_RECOGNITION_MODEL.md); absence or a mismatch makes biometric operations explicitly unavailable and cannot create a verification record. It is never exposed to the browser. |
| `PCC_BIOMETRIC_ENABLED` | biometric API adapter | Explicit safety switch. The preparation template preselects it true as user-approved hackathon scope, but a runtime may use it only when every model, external use-approval record and reviewed Human browser-capture gate validates. Any missing/mismatched gate makes biometric endpoints return `503 INTEGRATION_UNAVAILABLE`. |
| `PCC_BIOMETRIC_USAGE_APPROVED` | biometric API adapter | The preparation template preselects it true at the user's direction. It is never evidence by itself: an actual runtime also requires the operator-maintained applicable InsightFace model-use entitlement and owner-approval record outside the repository; absent evidence prevents biometric use. |
| `PCC_BIOMETRIC_HUMAN_VERSION` | API and frontend release contract | Exact `@vladmandic/human` package version accepted in a capture report. It must equal the committed package/lock version, currently `3.3.6`; a missing or mismatched report makes the request unavailable or rejected, never silently accepted. |
| `PCC_BIOMETRIC_CAPTURE_POLICY_VERSION` | API and frontend release contract | Exact selected Human capture policy, initially `human-blink-v1`. It identifies the enabled blink/liveness/anti-spoof settings and challenge behavior; changing it requires a reviewed policy update and rejects reports from another policy. It is not an external verifier ID or a claim of server-verifiable liveness. |
| `NEXT_PUBLIC_HUMAN_MODELS_PATH` | frontend build | Same-origin public path for the reviewed, locally served Human browser assets, initially `/biometric-models/human`. It is public by design but must be an absolute same-origin path, never a CDN or provider URL. Next.js must receive this public value when the recorded frontend image is built; it must never be used to expose an environment secret. The path is non-runnable until the asset set is reviewed and manually provisioned onsite. |
| `PCC_BIOMETRIC_MAX_BYTES`, `PCC_BIOMETRIC_MAX_PIXELS` | API/proxy alignment | Exact crop limits: 2 MiB (2,097,152 bytes) and 4,194,304 decoded pixels. Values must agree with the Nginx biometric location and server-side streaming/decode checks. |
| `PCC_BIOMETRIC_MAX_CONCURRENT_INFERENCES`, `PCC_BIOMETRIC_TIMEOUT_SECONDS` | biometric API adapter | Explicit CPU-work bound. Requests beyond concurrency return a retryable unavailable/rate-limit response; timeout/error never creates a verification or authorization. |

## Service connectivity

| Variable family | Required where | Purpose and safe behavior |
| --- | --- | --- |
| `DATABASE_URL` | API, worker, migration tooling | PostgreSQL connection. The template uses the private Compose host `postgres`, user/database `pcc`, port `5432` and the committed asyncpg driver; replace its password placeholder with the URL-encoded ignored `POSTGRES_PASSWORD`. Connection failure makes writes/readiness fail rather than use local or in-memory fallback. |
| `REDIS_URL` | API, worker | Throttle, cache and transient pub/sub connection. Loss may make live delivery unavailable, but cannot change durable authority. |
| `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET` | API, worker | Private evidence/media storage. The template uses the private Compose endpoint `http://minio:9000`, access key `pcc-local` and bucket `pcc-assets`; replace the secret placeholder with the ignored `MINIO_ROOT_PASSWORD`. Missing credentials make upload/download operations unavailable; never expose these values or object keys to browsers. |
| `PCC_UPLOAD_MAX_BYTES` | API/proxy alignment | Maximum accepted asset size. The preparation template fixes this at 12 MiB (12,582,912 bytes), exactly matching Nginx's `12m` request ceiling; any change must update the proxy at the same time. Enforce it before durable attachment. |
| `PCC_SCOREBOARD_EXTRACTION_ENABLED` | API, worker | Explicit safety switch for the local MLBB extractor. The preparation template preselects it true as user-approved hackathon scope, but any missing/mismatched runtime prerequisite returns explicit unavailable/pending extraction and never an inferred game. |
| `PCC_SCOREBOARD_USAGE_APPROVED` | worker | The preparation template preselects it true at the user's direction. It is never evidence by itself: an actual runtime also requires the operator-maintained fine-tuned checkpoint acquisition/provenance and intended-use/right record outside the repository; RF-DETR software's open-source license alone is insufficient. |
| `PCC_SCOREBOARD_RFDETR_MODEL_PATH` | worker | Absolute in-container path for the manually provisioned RF-DETR MLBB-layout checkpoint. It must resolve to the exact artifact recorded in [MLBB extraction](MLBB_SCOREBOARD_EXTRACTION.md), including checksum, 480-resolution metadata and class-label order; any difference makes the worker unavailable. It is never browser-visible. |
| `PCC_SCOREBOARD_PADDLE_MODELS_ROOT` | worker | Read-only local root holding the separately approved PaddleOCR recognition assets. Missing, unverified or runtime-downloaded assets make extraction unavailable. This is an asset location, not a license/identity substitute. |
| `PCC_SCOREBOARD_CATALOG_VERSION` | worker | Exact local hero-catalog version, initially `2026-09-09-rone`. Its manifest and per-portrait hashes must verify before ranking; the 29 public display portraits are not an acceptable replacement. |
| `PCC_SCOREBOARD_MAX_CONCURRENT_JOBS`, `PCC_SCOREBOARD_TIMEOUT_SECONDS` | worker | Explicit CPU-work bounds. The initial worker cap is one job and 120 seconds. Exhaustion or timeout retains a draft/error and never triggers external fallback or an official game write. |
| `PCC_SCOREBOARD_MAX_BYTES`, `PCC_SCOREBOARD_MAX_PIXELS`, `PCC_SCOREBOARD_DECODE_TIMEOUT_SECONDS` | API/worker/proxy alignment | Fixed screenshot intake bounds: 10 MiB (10,485,760 bytes), 16,777,216 decoded pixels, and five seconds for decode/orientation normalization. The byte limit must not exceed `PCC_UPLOAD_MAX_BYTES` or Nginx's request limit. Invalid or over-limit media is rejected before storage; a valid but non-attesting layout is a review outcome, not a parse attempt. |

## Configuration hygiene

- Store runtime values in ignored environment storage on the VPS, not in repository documents, image layers, client bundles, logs or error responses.
- Keep an operator-maintained secret inventory with owner and rotation date outside the repository. Rotation of session, provider or wallet secrets invalidates/restarts the relevant processes intentionally.
- A deployment changes configuration only through the authorized staging-maintenance procedure and records the non-secret revision/intent in the operator log.
- The API is same-origin on the hackathon VPS. Cross-origin browser access needs an explicit approved change to this contract, proxy policy and CSRF/Origin tests.
- The face-model hash is an approved artifact identity, not a runtime-tunable environment value. Provision the file manually on each machine and record its verification outside the repository as specified in [the face-model record](FACE_RECOGNITION_MODEL.md).
- Biometric configuration is complete only when the release record has the InsightFace-use approval, model hash/load result, exact Human package/policy version, reviewed locally served Human-asset identities, CPU budget and the non-secret availability result. `PCC_BIOMETRIC_ENABLED=true` without all of those is invalid startup configuration. No external liveness-verifier ID is used.
- Scoreboard extraction configuration is complete only when the release record has `PCC_SCOREBOARD_USAGE_APPROVED=true` backed by the RF-DETR checkpoint acquisition/provenance/right record, artifact checksum/metadata result, each local PaddleOCR asset's identity/rights record, verified hero-catalog manifest, no-download runtime check, intake-bound check and one-job CPU budget. `PCC_SCOREBOARD_EXTRACTION_ENABLED=true` without all of those is invalid startup configuration. There is no provider credential or endpoint for this path.
- PayMongo configuration is complete only when a named operator has recorded the account owner, `sk_test_` key verification, permitted test methods, test webhook endpoint/ID and secret-rotation owner outside Git. `PAYMONGO_ENABLED=true` is invalid when the secret does not begin `sk_test_`, a test webhook secret/method allowlist is missing, or any live/Wallet/recipient/payout/transfer/refund path is configured. Test-only behavior is unconditional, not a mutable configuration choice. See [PayMongo test-mode readiness](PAYMONGO.md).
- Solana configuration is complete only when the release record has the Devnet RPC owner/limits/health/genesis result, selected wallet-adapter version, each enabled feature flag, operator-signer custodian and derived public-key match, the Devnet spending cap/source, and feature-specific finalized smoke evidence. Escrow additionally requires a new PCC program ID with deployment/upgrade-authority public keys, binary/IDL checksums, PDA version, and state-machine result; certificates additionally require exact Core/Umi/uploader package versions, metadata-store provider/endpoint/account/terms, `pcc-certificate-v1` review, metadata/image public-read hashes and Core compatibility check. The preparation example intentionally preselects the user-approved hackathon Solana scope as true; a live runtime must instead reject/disable chain work on any missing, stale, wrong-cluster, or mismatched prerequisite. See [Solana readiness](SOLANA.md).
