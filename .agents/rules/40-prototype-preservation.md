# 40: prototype preservation

The approved frontend baseline is the final design and interaction authority. Recreate its public editorial Manrope surface and portal Plus Jakarta Sans/light-workspace/dark-sidebar surface without redesign. Preserve its responsive, reduced-motion, WebGL fallback, keyboard, contextual breadcrumb and privacy behavior.

Read the self-contained [onsite reconstruction blueprint](../../docs/screens/ON_SITE_BLUEPRINT.md), [frontend ownership structure](../../docs/FRONTEND_STRUCTURE.md), [exact route compositions](../../docs/screens/ROUTE_CONTRACTS.md), [cross-feature breadcrumb-context contract](../../docs/screens/BREADCRUMB_CONTEXT.md), [layout and data-presentation contract](../../docs/screens/LAYOUT.md), [controls inventory](../../docs/screens/CONTROLS.md), [tokens](../../docs/screens/TOKENS.md), [CRUD binding matrix](../../docs/screens/CRUD_MATRIX.md), [visualization semantics](../../docs/screens/VISUALIZATIONS.md), [component catalogue](../../docs/screens/COMPONENT_CATALOG.md), [asset readiness](../../docs/screens/ASSET_READINESS.md), [screen families](../../docs/screens/README.md) and [baseline expectations](../../docs/acceptance/FRONTEND_BASELINE.md) before UI work. Preserve a valid cross-feature trail and its origin sidebar item, but resolve it only through the server-filtered navigation context; URL query values never grant access or supply labels. Replace simulation/local success with truthful server-backed pending, failed or verified states.

Use the version-pinned, selective shadcn/ui primitive layer in the component catalogue after onsite authorization. Do not install every registry component or let default shadcn cards, charts, sidebars, data tables, templates, colors or spacing override the approved PCC design; build the documented PCC custom components on top of the needed accessible primitives.
