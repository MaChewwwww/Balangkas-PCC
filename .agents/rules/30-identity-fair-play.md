# 30: identity, fair play and reward safety

Use authenticated session principal for ownership. Never generate acting-user IDs, accept client ownership fields, substitute random face vectors or report verified when inference/dependencies fail. Biometric flow retains normalized embedding only after consent/liveness and duplicate comparison; raw frame is discarded.

Wallet linking requires signed challenge and separate biometric authorization. Monetary values are exact centavos/lamports. Payout/issuance requires verified evidence, authorized release and idempotency. User certificate recipient needs a linked wallet; team custody is a separate explicit mode.
