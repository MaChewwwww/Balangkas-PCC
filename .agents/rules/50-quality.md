# 50: quality and validation

Every onsite feature change requires focused unit/integration coverage and, where valuable, fast Vitest component tests. Every data change requires migration rendering, empty database upgrade and seed verification. A changed portal cross-feature link also checks the allowed-chain, safe-fallback and sidebar behavior in [the breadcrumb-context contract](../../docs/screens/BREADCRUMB_CONTEXT.md). Do not create or require automated browser E2E or visual-regression suites during this hackathon: the developer completes [the manual UI report](../../docs/screens/MANUAL_UI_REPORT.md) for the checked routes, states/actions, widths and keyboard/focus result in the handoff or PR. Mock providers in CI; never send payments or sign live transactions in ordinary tests.

Immediate scrimmage result behavior is fixed: one authorized participating leader finalizes atomically; identical retry returns same result; conflicting later input returns 409. No timer/worker/dual-confirmation fallback may be reintroduced without an explicit decision update. Follow [testing](../../docs/TESTING.md).
